# Task 98: Plan templates don't reference standards skills

## Description

Plans generated by `sdd-change` are generic checklists that never reference which plugin standards skills apply to each phase. This is both a human-readability and execution problem:

- **Execution:** Plans are the execution script for `sdd-change implement`. Without standards references, there's no explicit contract between the plan and the standards. Agents *probably* follow their standards (they're wired in via frontmatter), but the plan doesn't reinforce it.
- **Human-readability:** A reviewer reading a PLAN.md can't tell which standards apply to which phase without also reading agent definitions.
- **Verification gap:** `sdd-change verify` checks standards compliance after the fact, but plans never told agents which standards to follow upfront.

### Files to update

1. `plugin/skills/change-creation/templates/plan-feature.md` — Add `Standards:` per phase, methodology-aware tasks
2. `plugin/skills/change-creation/templates/plan-bugfix.md` — Same
3. `plugin/skills/change-creation/templates/plan-refactor.md` — Same
4. `plugin/skills/change-creation/templates/plan-epic.md` — Review (may not need per-phase standards)
5. `plugin/skills/planning/SKILL.md` — Update template section (lines 210-308) to match, update Plan Content Guidelines to acknowledge standards references belong in plans

### What compliance looks like

Each phase should have:
- A `Standards:` field listing applicable skill names
- Task descriptions that are methodology-aware (e.g., "Implement Model layer" not "Implement domain logic")

Example:
```markdown
### Phase 2: [Component Name] - Backend Implementation
**Agent:** `backend-dev`
**Component:** <component-name>
**Standards:** `typescript-standards`, `backend-standards`, `database-standards`, `unit-testing`

Tasks:
- [ ] Implement Model layer (definitions + use-cases with dependency injection)
- [ ] Implement DAL layer (one function per file, parameterized queries)
- [ ] Wire Controller layer (HTTP handlers, create Dependencies)
- [ ] Write unit tests per layer using TDD (red-green-refactor)
- [ ] Add telemetry (structured logging, metrics, spans)
```
