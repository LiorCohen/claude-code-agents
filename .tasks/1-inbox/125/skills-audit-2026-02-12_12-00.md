## Systemic Violations

### 1. Vague "refer to" pattern (14 skills)

The pattern `"refer to the project-settings skill for X"` appears in 14 skills with 16 instances. This violates the self-containment rule: cross-references must describe the delegation contract (what goes in, what comes out, where responsibility lies), not just tell the reader to go read another skill.

**Common pattern (BAD):**
```
refer to the `project-settings` skill for schema
```

**Expected pattern (GOOD):**
```
Delegate to the `project-settings` skill for directory path resolution.
It maps component type + name to a filesystem path (e.g., server/main → components/servers/main/).
```

**Affected skills:** backend-scaffolding (×2), helm-scaffolding, config-scaffolding, contract-scaffolding, database-scaffolding, helm-standards, commit-standards, planning, local-env, change-creation, integration-testing, e2e-testing

## Recommended Fix Priority

### P1 — High Impact, Low Effort

1. **Fix the 1 code block missing language specifier** in typescript-standards (line 404: add `text` language).

2. **Standardize the "refer to project-settings" pattern** across 14 skills. Create a consistent delegation sentence and apply to all 16 instances. Example fix:

   ```
   # For directory mapping references:
   "Directory paths are resolved by the `project-settings` skill, which maps
   component type + name to filesystem paths (e.g., type=server, name=main →
   components/servers/main/)."

   # For schema references:
   "Component settings schema and defaults are defined by the `project-settings`
   skill. It accepts component type and returns the typed settings object with
   validation rules."
   ```

### P2 — High Impact, Medium Effort

3. **Split typescript-standards** (1,055 lines, 2.1× limit). Consider extracting into focused sub-skills:
   - Core TypeScript patterns (types, imports, error handling)
   - Module/architecture patterns (barrel exports, project structure)

4. **Split workflow-state** (764 lines, 1.5× limit). Consider extracting state machine definitions or validation logic into separate reference files within the skill directory.

5. **Fix the circular dependency** between workflow-state and spec-solicitation. One option: have both reference a shared contract definition rather than each other.

### P3 — Medium Impact, Medium Effort

6. **Reduce remaining oversized skills** (8 skills, 515–639 lines). Prioritize by overage:
   - spec-decomposition (639) — extract scoring rubric or examples
   - e2e-testing (619) — extract Playwright config examples
   - spec-writing (595) — extract templates into separate template files
   - external-spec-integration (559), postgresql (555), frontend-standards (553), integration-testing (553) — trim examples or extract reference sections
   - spec-solicitation (515) — minor, could fix with vague-ref cleanup

7. **Fix vague cross-references** in spec-solicitation (lines 500-501) and spec-decomposition (line 472) — these are skill-to-skill refs outside the project-settings pattern.
